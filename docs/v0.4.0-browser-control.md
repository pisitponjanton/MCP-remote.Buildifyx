# v0.4.0 — Browser Control Tools

Browser MCP operations run in an isolated local Chromium session with explicit Agent-side permission checks. Availability depends on the installed version, browser installation and local authorization.

## Tools

| Tool | Inputs | Behavior |
| --- | --- | --- |
| `browser_open` | `url?`, `kind?=temporary`, `profileName?`, `confirmPersistent?` | Opens isolated Chromium profile and optional HTTP(S) URL; returns owner-scoped session and tab IDs |
| `browser_navigate` | `sessionId`, `tabId?`, `url`, `timeoutMs?` | Navigates after URL validation and returns title, final URL, HTTP status |
| `browser_snapshot` | `sessionId`, `tabId?`, `maxChars?` | Returns bounded visible page text and up to 100 element summaries; no input values/cookies |
| `browser_click` | `sessionId`, `tabId?`, `target`, `timeoutMs?` | Clicks one visible, unique, non-sensitive element |
| `browser_fill` | `sessionId`, `tabId?`, `target`, `value`, `timeoutMs?` | Fills text input or textarea, never returns the value; blocks password/file fields |
| `browser_tabs` | `sessionId`, `action?=list`, `tabId?` | Lists, selects, opens or closes tabs (max 5 tabs/session) |
| `browser_close` | `sessionId` | Closes one session and cleans temporary data without deleting persistent profiles |

Targets are mutually exclusive `{selector}`, `{role,name}` or `{text}` and must match exactly one visible element. Timeout defaults to 10–12 seconds, maximum 30 seconds. Snapshot text is capped at 12,000 characters. URLs are capped at 4096 characters and must use HTTP(S).

## Authorization and ownership

- Browser tools require new distinct permission categories: `browserRead`, `browserNavigate`, `browserInteract`, plus separate `persistentProfile` for `browser_open` with `kind=persistent`. They default to **Ask** regardless of legacy `read/write/command` policy or unrestricted command mode.
- Opening a persistent profile requires **both** `confirmPersistent=true` and approved `persistentProfile` policy/prompt. Plain browser navigation authorization does not grant persistent profile access.
- MCP clients cannot supply their own principal or instance. The CLI binds a real instance ID and a trusted local OS-user namespace or a credential-derived Cloud device principal fingerprint. Browser sessions are additionally fenced to the owner's canonical workspace and device identity.
- Local and Cloud use the same Agent runtime tool dispatcher, JSON schemas, authorization/approval flow and manifest. Existing Agent Protocol v2/Management Protocol v1 remain unchanged; there is no new public listener.
- `browser_fill` values are removed from tool-start Audit logs and approval-request inputs; returned results include only `filled` and length. Browser page content is **untrusted**.
- Clicking submit controls, password/file inputs, download links, cross-origin anchors and obvious destructive/payment buttons returns `BROWSER_SENSITIVE_ACTION`. The Phase 6 engine does not attempt purchases or form submissions autonomously.
- `browser_tabs` actions `new` and `close` require `browserInteract`; listing/selecting require `browserRead`.
- Browser sessions are held in memory with a 3-session aggregate Agent-tool limit, 5 tabs/session, plus the Phase 5 30-minute inactivity eviction and shutdown cleanup.

## URL and network controls

- Accepts loopback HTTP(S) for local development (`localhost`, `127.0.0.1`, `::1`).
- Rejects file, data, javascript and embedded-credential navigation; denies obvious private, link-local, carrier-NAT, metadata, multicast and internal destinations.
- **R02 per-tab origin isolation (Phase 13):** every explicit browser navigation grants a single allowed Origin only to its target tab, replacing that tab's previous grant. Requests from other tabs, unapproved redirects and popups, and requests without a known page cannot reuse it. Existing Playwright route interception and public-hostname DNS safety validation remain enabled; `test/browser/r02-origin-isolation.test.js` covers two-tab GET isolation, valid same-origin resources, rejected redirects/popups, and DNS.
- **F01 hardening (Phase 13):** `browser_click`/`browser_fill` without explicit Sensitive Approval are limited to local DOM changes. GET can mutate state on badly designed websites, so script `fetch`/XHR GET is blocked by default and all network requests **from that tab** are blocked after a safe interaction until explicit `browser_navigate` **of the same tab**. Navigation or Sensitive Approval in another tab cannot unlock it. `confirmSensitive:true` plus `browserSensitive` approval permits same-origin requests only on the approved tab and only during the approved action. Ordinary same-origin links may need an explicit navigation call. This is intentionally fail-closed, not an OS-enforced browser sandbox.
- **Important:** This is a Phase 6 baseline, not complete protection against DNS rebinding, privileged internal networks or all website-initiated navigation/fetch actions. Phase 8 must add stronger per-origin consent, DNS pinning, popup/redirect and network egress rules, including sensitive submission classification. Browser permissions should remain Ask/Deny until these controls are validated in production.
- The existing Local MCP gateway is loopback-only but has documented local access risks; exposing it outside localhost is not recommended.

## Tests

- `test/browser/control.test.js`: tool schemas, permissions, privacy-safe results, navigation and interaction against real Chromium localhost fixtures, sensitive control denial and tab management.
- `test/cli/local.test.js`: actual subprocess Local MCP gateway tools/call → Agent → Chromium → JSON response including snapshot/navigate/close.
- Existing Chromium/session, image/media, Cloud and management tests should remain green. Native Windows/Linux Playwright/IPC smoke and production Cloud/ChatGPT interoperability remain Phase 9–11 validation.
- No screenshot tool, UI diagnostics tool, Playwright browser installer or release version bump in this phase.
