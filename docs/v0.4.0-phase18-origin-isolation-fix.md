# Phase 18 — Fix pending Browser origin isolation and redirect-chain bypass (2026-10-13)

**Scope:** Agent v0.4.0, branch `cloud`. Fix the **High** Browser Origin Isolation finding from final read-only Phase 12 / Plan Revision 29. No Cloud Backend edits, commits, pushes, npm publish, deploy, production login or real ChatGPT traffic.

## Root causes verified (before changes)

1. `guardBrowserContext.allowNavigation` immediately set the approved origin for a tab, **before** the old page was replaced by a trusted navigation. An old page with a repeating GET image beacon could therefore send to that *new* origin before `page.goto` began. The isolated real Chromium / two-local-server repro observed dozens of unexpected GET requests.
2. `route.fulfill({response})` for an HTTP **302** could cause Chromium to follow subsequent redirects without invoking the Playwright `route` callback for each hop. A same-origin redirect followed by a second, cross-origin redirect reached the forbidden server **before the Agent validated the final URL**. The new real-Chromium negative test recorded 1 forbidden GET before the fix.

## Changes

- `src/browser/network.js` maintains a **per-tab pending navigation** containing the requested origin/URL, verified served document URL, real frame-commit state, and a trusted next redirect target. While pending and before that verified main document commits, **all** unrelated requests from the former page (including `GET` images, even if a mutation was previously approved) are blocked; only the exact explicitly requested main-frame document or its verified chain is eligible.
- New-page ordinary same-origin resources are enabled when its verified document response has actually committed to the main frame; they **do not** require prematurely confirming the overall Agent `browser_navigate` result. Cancellation and failed navigations remove the pending grant; other tabs cannot borrow it. Safe-click network locking persists until successful Agent confirmation.
- The guard now intercepts an HTTP document **30x** and validates `Location` and origin, but responds with a **local harmless 200 redirect stub** rather than letting Chromium follow it. A private `takeRedirect(page, requestedUrl)` hands the verified next URL back to `src/services/browser.js`. Only the trusted Agent then issues a **fresh, separately intercepted** `page.goto` for that URL.
- The Agent follows **at most 8 document steps**, with checks at each step; repeated redirect loops fail with `BROWSER_NAVIGATION_FAILED`. A cross-origin redirect fails *before sending a GET to the forbidden destination*. Legitimate same-origin chains reach the real final URL, have the expected title/content and load assets **once per URL**; no duplicate GET preflight.
- Untrusted Playwright/network failures remain sanitized. Permission revocation and cancellation maintain their typed error codes from the earlier Phase 18 fix. Cross-origin redirects and currently unverified non-document subresource redirects are intentionally fail-closed.

## New regression / Red → Green

`test/browser/phase18-pending-origin.test.js` contains five Chromium-backed cases:
1. Old-document image-beacon requests to the newly allowed origin remain zero before the explicit new document navigation; a redirect and its final-page assets still work.
2. A different tab's navigation permission is not inherited by an old document; cancel removes the grant and no leakage occurs.
3. A same-origin first redirect followed by a forbidden cross-origin second hop cannot reach the forbidden server.
4. Two legitimate same-origin redirects produce the final page, with one HTTP request each for initial/intermediate/final paths and one image request.
5. A redirect loop is stopped at the 8-hop limit.

The first cases reproduced the security defect **before** the production fix (35 and 14 unexpected GETs in separate runs), and the multi-hop test independently reproduced 1 unauthorized cross-origin GET. After code fixes **all 5/5 pass** on real Chromium. The original `test/browser/f01-network.test.js` and `test/browser/r02-origin-isolation.test.js` mock expectations were updated to distinguish a merely pending grant from a truly committed document. Both suites pass, as do all other Browser, TUI, Image, Cache, Media, Cloud Transport and CLI tests.

## Regression, scope and known limitations

- **Mac ARM64 / Node.js 24.20.0 full Agent source regression: 63/63 test files PASS** (Browser 15, Transport 7, Image/Cache 5, Permissions/Core 5, Media 7, TUI 6, Release 3, CLI 5, Services 3, Workspace Plan 5, Misc 2). All run in manageable independent batches, including final 5/5 new Chromium checks.
- JavaScript syntax, package dry-run and `git diff --check` must pass following this documentation update; see final validation in the Phase completion report.
- **Behavioral trade-off:** Redirects of non-document subresources (such as images redirected by HTTP) fail closed. The synthetic 200 redirect stub does not replay response-body, cookie or miscellaneous original 30x response metadata; cookie-setting redirect flows may behave differently. The explicit document redirect chain (same-origin, bounded) is tested.
- **Security boundary:** Chromium/Playwright's request-routing guard remains in-process. No OS firewall, DNS pinning or arbitrary-hostile-site isolation guarantee. Source-code/controlled WebSocket and Chromium tests **do not** prove live ChatGPT/Cloud E2E, native Windows CI or a genuine signed-in device upgrade; these still carry **LIVE NOT TESTED** labels from Phases 13/17.
- Completing this **Fix Review Findings** phase is **not** an approval to ship. Phase 12 must rerun as **read-only final diff review** and independently pass. Release remains **HOLD** until an explicit release decision.
