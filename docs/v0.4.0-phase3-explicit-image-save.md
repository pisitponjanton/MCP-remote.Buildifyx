# v0.4.0 — Phase 3: Explicit Workspace Image Save & Error UX

Date: 2026-10-15
Task: ChatGPT Image Attachment → Agent Workspace Transfer
Disposition: **Agent runtime save flow verified; minimal approval/error UX fix applied.**

## What changed

- `src/permissions/evaluator.js`: `describeRequest('save_cached_image', {destinationPath})` now includes the actual destination in the local approval description. Previously, a user reviewing an `imageSave=ask` prompt saw only `save_cached_image`, without the target filename. The filename appears in a local user-initiated approval context, not in a public error.
- `src/core/errors.js`: The stable public codes `IMAGE_EXISTS`, `IMAGE_PATH_DENIED`, `IMAGE_PATH_CHANGED`, `MEDIA_IMPORT_PERMISSION_REQUIRED`, and `CACHE_NOT_FOUND` now have actionable generic messages. The original exception's path, URL or token remains withheld. Structured codes and caller permissions remain unchanged.
- `test/image/phase3-explicit-import-save.test.js`: Disposable-runtime regression on PNG, JPEG and WebP imported into private RAM and accessed through `runtime.dispatch('get_cached_image')` followed by explicitly authorized `runtime.dispatch('save_cached_image')`; SHA-256 and file bytes match; no file before save. Covers imageSave Deny/Ask/Allow, approval destination visibility, existing file preservation, traversal/symlink escape, independent outsideRoot and imageSave fencing, and invalid artifact ID.
- `test/image/phase3-public-errors.test.js`: Confirms errors remain actionable and do not disclose arbitrary internal exception content.

## Observations / contracts

1. Cloud import already yields `artifactId`, MIME/size/SHA-256 after verification and Sharp decode, with no disk write. `get_cached_image` returns metadata for an authorized imported artifact. Reusing a previously imported ID on a different workspace does not bypass the owner's cache.
2. An imported image is eligible for an explicit save only through `save_cached_image({artifactId,destinationPath})`. That tool requests independent `imageSave` authorization. Existing import access still requires `imageRead=allow` plus `cacheManage=allow` at import/read/save checkpoints. A Cloud transport frame never auto-saves files.
3. The destination is reclassified immediately before write within the approved root, and the write uses exclusive new-file creation. Repeated destinations fail `IMAGE_EXISTS`, symlinks/traversal outside roots fail authorization, and original files remain unchanged. The explicit-save test covers PNG/JPEG/WebP bytes and checksum.
4. Approval under Ask is a locally resolved prompt; no blanket permission escalation, hidden auto-approval, separate Cloud credential operation, or outsideRoot bypass was introduced.
5. Image Save error output now tells the caller what can safely be done (choose a different filename, choose an approved root, reimport temporary content). Messages do not reflect arbitrary lower-level error content.

## Limitations / next steps

- Tests use isolated image fixtures and an Agent runtime/local mock WebSocket, **not** a real ChatGPT-hosted attachment, a production user's account, or a deployed Cloud session. Real host-to-Cloud file transfer remains BLOCKED/UNVERIFIED pending separately owned Cloud file-input support.
- Full npm tests, native OS matrix, packaging and production rollouts belong to Phase 6. Phase 4 must separately exercise transfer integrity/revocation/expiry/memory cleanup and principal/instance/session isolation with adversarial fixtures; successful Phase 3 tests are not a substitute.
- This Phase does **not** commit, push, publish, deploy, restart agents, or change any live permission or workspace.
