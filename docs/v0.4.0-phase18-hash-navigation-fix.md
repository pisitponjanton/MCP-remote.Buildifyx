# Phase 18 — Fix Same-document/Fragment Navigation Unlock (2026-10-13)

**Scope:** Agent v0.4.0, workspace `MCP-remote.Buildifyx`, branch `cloud`, uncommitted working tree. This is **only the latest Phase 18 fix review** for the High finding recorded by Phase 12 at Plan Revision 33. No Cloud backend edits, Git commit/push, npm publish or deployment.

## Finding and read-only reproduction

`src/browser/network.js` allowed `confirmNavigation(page, value, null)` whenever the normalized URL matched `pending.url`, then **deleted `safeLockedPages` and `pendingNavigations`**, even when the original untrusted document remained active. Playwright `page.goto(oldURL#fragment)` returns `null` for a same-document navigation. A safe-click-locked old page could then send unintended image GET requests because the guard incorrectly reported a completed navigation. The read-only real Chromium reproduction from Phase 12: **0 GET hits before hash navigation; `confirmNavigation=true`; 34 unexpected GET hits after**.

## Fix (fail closed)

- `src/browser/network.js` `confirmNavigation()` **never clears the old-document network lock for a null/absent Playwright Document Response**. URL equality, fragment/hash changes, History API same-document events, or previously authorized origin alone cannot prove a document replacement.
- For successful navigation confirmation, require **all**: pending grant exists with no unconsumed redirect, trusted `response.request()` matches the intended main-document route and redirect chain, **`pending.documentCommitted === true` from a distinct CDP main-frame loader ID**, `pending.servedDocumentUrl` is recorded from a verified route-fetched document, and `page.url()`, the committed target and served-document URL agree.
- Real `browser_navigate` to same URL with only `#fragment` therefore fails with `BROWSER_NAVIGATION_FAILED` and cancels its temporary network grant. The existing safe-click lock is retained: **no GET image beacon or background subresource from the original page is permitted**. This is a conservative UX compatibility trade-off; the navigation may have changed the fragment without replacing the document, but it is **not** treated as a completed new navigation.
- No permissive fallback was introduced. Existing Chromium CDP new-loader verification, per-tab scope, same-origin verified redirect chain (up to 8 checked steps), request cancellation and Cloud duplicate-ID handling remain unchanged.
