# Phase 14 — Terminal Image / Cache / Browser permissions (2026-10-13)

**Scope:** Agent TUI only. No Cloud change, credential change, automatic permission grant, token/profile creation or commit/publish/deploy.

## Implemented

- The **Permissions** screen now exposes **all 16 policy categories**, grouped into **Base permissions (5)**, **Images and cache (3)** and **Browser permissions (8)**. The category registry is shared by the keyboard handler and the visible rows, avoiding invisible or non-selectable permissions.
- The list is **viewport-scrolled** based on calculated terminal rows. The chosen category remains visible when navigating all 16 using **Up/Down**; the active group and selection index remain visible in a fixed line even when its group heading has scrolled off-screen. Labels are truncated to fit narrow terminals; Ink's existing minimum-size fallback remains intact.
- **Left/Right** and **Space** change the selected category's **actual effective ALLOW / ASK / DENY** using the instance's existing `policyManager.setCategory` API. No new storage path or shared/global policy is introduced. Displaying pre-v0.4.0 partial policies uses existing default values (11 advanced categories initially ASK) without saving or escalating them.
- The legacy **A Auto**, **O Read-only**, **F Allow** presets continue to change **only the five base categories**. Their header/footer/help labels now explicitly say **base 5**, not misleading **Allow all**. Advanced categories are **independently controlled**, including `browserExternal`, `browserSensitive`, `persistentProfile`; presets must not elevate previously ASK/DENY values. The footer separately summarizes current advanced Allow/Ask/Deny totals.
- The Terminal help and Permissions controls describe the keyboard shortcuts; existing roots, command rules, dashboard, background handoff, and approval handling are otherwise unchanged. **Global approval visibility on every screen is Phase 15, not part of this change.**

## Evidence

- `test/tui-permissions.test.js`: 5 focused tests on exact 16-category coverage, grouping, effective decisions for stored legacy policies, advanced-state counts, active selection visibility on **160×50, 100×30, 80×23 and 52×24** terminals, and all A/O/F presets preserving advanced permission state.
- Existing `test/tui-layout.test.js`, `test/tui-model.test.js`, `test/tui-profiles.test.js` and `test/tui-remote.test.js` remain applicable.
- Existing `test/permissions/policy.test.js`, `test/permissions/concurrency.test.js`, `test/local-file-permissions.test.js`, `test/cli/local.test.js`, `test/core/runtime.test.js` are included in regression checks.

## Boundaries

- This phase updates the selection/edit display and labels. It does **not** implement Phase 15's global approval overlay or Phase 16's cancellation/error diagnostics; Phase 17 is reserved for broader TUI interaction and Cloud permission regression.
- Live hosted Cloud/ChatGPT ImageContent, native Windows CI, real signed-in production device upgrade and OS-level browser network egress containment remain unverified or caveated as recorded in Phase 13's code-level closeout.
- Release remains **HOLD** until subsequent phases and final review are completed.
