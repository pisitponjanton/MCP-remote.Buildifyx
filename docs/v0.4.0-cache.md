# v0.4.0 — Local Image Artifact Cache

Temporary artifacts are owner- and workspace-scoped. Cache management is distinct from permanent files, and local permissions govern read, save and deletion operations.

## Modules

- `src/cache/identity.js`: stable per-install `deviceInstallId`, canonical workspace identity, authenticated principal identity and separate `local`/`cloud` namespaces. Owners are versioned, hashed paths; an ephemeral `instanceId` is not the owner.
- `src/cache/store.js`: temporary, owner-scoped data and metadata, creation/reads, leases, cleanup, eviction, deletion and audit callback.
- `test/cache/store.test.js`: ownership isolation, identity restart, atomic writes, quota, TTL, leases, lock recovery, symlink safety, integrity checks and protection of project files.

Storage is confined to `~/.buildifyx/cache/device-install.json` and `~/.buildifyx/cache/v1/owners/<ownerKey>/{meta,data,leases,tmp}`. No user-defined filename is used in a cache path. Parent Cache/Owner directories are checked to prevent symlink traversal. Files/metadata are mode 0600 and directories mode 0700 where supported. Browser data is **not** stored here: later phases use separate temporary session and opt-in persistent-profile directories.

## Internal API

`createArtifactCache({ workspaceRoot, namespace = 'cloud', principalId, homeDirectory, ttlMs, quotaBytes, maxArtifactBytes, cleanupIntervalMs, now, audit })` returns:

- `initialize({ periodic = false })`: startup garbage collection and optional unref'd periodic cleanup. `close()` clears the timer.
- `identity()`: returns stable `ownerKey`, `namespace` and `deviceInstallId` for internal diagnostics (never a credential).
- `put({ data, kind, mimeType, origin, expiresInMs, pinned })`: Buffer/Uint8Array only; stores temporary artifact atomically and returns sanitized metadata and opaque `art_<uuid>` ID.
- `get(id)`: returns `{metadata, data}` after checking ownership, expiry, length and SHA-256.
- `withLease(id, async ({metadata,read}) => ...)`: keeps the item from being removed during in-flight reads/transfers; only use `read()` while the lease is active.
- `list()` / `remove(id)` / `clear()` / `setPinned(id, boolean)` / `prune()`: owner-only enumeration/mutations, deletion and quota housekeeping. Pinned files are protected from **quota eviction**, not from expiry or explicit clear; pinning is **not** permanent save.

Example internal use **after caller authorization and current Workspace routing has been checked**:

```js
import { createArtifactCache } from './src/cache/store.js';

const cache = createArtifactCache({
  workspaceRoot: '/authorized/workspace',
  namespace: 'cloud',
  principalId: resolveCloudCachePrincipal(authenticatedDeviceCredentials),
  audit: (event) => eventBus.emit(event.type, event)
});
try {
  await cache.initialize({ periodic: true });
  const asset = await cache.put({
    data: imageBytes, kind: 'image', mimeType: 'image/png', origin: 'generated'
  });
  const { data } = await cache.get(asset.id);
} finally {
  cache.close();
}
```

**F03 account scoping and safe migration (Phase 13):** The running Cloud Agent derives a hashed `cachePrincipalId` from the authenticated Cloud origin and stable user ID in the login response; older stored credentials fall back to normalized account email. For credentials with no account data, a hash of the issued device ID **and token** is used to prevent cross-account reuse; that fallback does not preserve temporary artifacts after token rotation. A cache owner is hashed from install identity + namespace + canonical workspace + authenticated cache principal. Local namespace remains separate. A custom in-process cache must be bound before initialization; changing principals or passing an initialized unscoped cache into an authenticated runtime fails closed. The caller never supplies the principal through MCP arguments.

Old pre-F03 `owner_...` directories have **no verified account identity** and are intentionally not migrated or assigned to the next account signing in. Their artifacts are not readable through authenticated Cloud tools. These temporary files are left on disk without a destructive migration; normal expiry/cleanup may eventually remove them. User-saved files and user-approved Browser Profiles are unaffected. The global device quota is retained, but a principal-bound cache may only quota-evict its own artifacts; if another account consumes the quota, new writes fail rather than evict someone else's temporary images.

The above is not a new MCP endpoint and does not give ChatGPT a cache tool or transfer API. Only explicitly authorized service code should construct a cache for a workspace. The module alone cannot verify Buildifyx Cloud's MCP Enabled gating or a user's browser consent; those must be checked by the Cloud/Agent tool path in later phases.

## Defaults, guarantees and limits

| Area | Phase 2 behavior |
| --- | --- |
| TTL | Default 24 hours, configurable per manager; expired objects are rejected and removed on cleanup, even if pinned |
| Per-device quota | Default 1 GiB globally; unbound legacy managers may evict globally, authenticated principal-bound managers may evict only their own artifacts |
| Max single object | Default 32 MiB input limit; image decoding and pixel limits are **not** implemented until Phase 3 |
| Atomic write | Private exclusive temporary file, fsync file, atomic rename to opaque data path followed by metadata; interrupted partials are reclaimed |
| Integrity | SHA-256, byte length, regular-file / hardlink rejection; nofollow open where OS supports it |
| Race control | Cache-wide filesystem directory lock; stale-lock recovery; per-artifact leases with heartbeat and stale-lease cleanup |
| Crash recovery | Removes expired metadata/data, invalid entries, missing-sidecar data and abandoned staging without recursively removing arbitrary directories |
| Audit | Optional deletion event callback with id, ownerKey, byte size and reason; no image content, original workspace path, cookies or tokens |
| Error behavior | Invalid, unknown, corrupted, expired, leased or unsafe entries fail closed with explicit errors |
| User files | Never deletes from the authorized workspace or other user paths; permanent save belongs to Phase 3 |

The per-device quota is enforced by instances configured with the **same global limits**. A caller can customize limits for tests or deployments, but Phase 3 must ensure consistent policy across processes. The cache should run `initialize({ periodic: true })` once per Agent process and `close()` on shutdown. Lease recovery uses a bounded freshness window; readers must not block their heartbeat event loop for longer than that window.

## Phase boundaries

Phase 2 deliberately **does not** register MCP tools, change the manifest, enable image transfer, install Playwright, alter v0.3.3 Cloud/Agent protocols, or save images permanently. The `mimeType` value is syntactically validated but **is not byte-sniffed yet**; MIME magic/decode/pixel validation, permissions and destination handling are Phase 3/8 responsibilities.

When Phase 3 integrates this manager, validate real image formats, never expose raw internal filesystem paths, and authorize the active namespace/workspace/device **before** using any artifact ID. Phase 4 must use small authenticated chunks instead of serializing a large Buffer inside a Cloud or Local JSON tool result.
