# Phase 18 — Fix Final Review Findings (2026-10-13)

**Scope:** Agent v0.4.0 / branch `cloud`. Fix the two blocking findings recorded by the failed Phase 12 final review (Revision 27). The changes and tests below are on the Agent workspace only. No Cloud backend edits, real credentials, deployment, commit, push, publish or live ChatGPT test.

## Fix 1 — HIGH: Duplicate Cloud Request ID erases original in-flight tracking

**Before:** `src/transport/cloud.js` used `activeCalls.add(requestId)` on each `tool.call` and `activeCalls.delete(requestId)` in each call's `finally`. A second concurrent frame with the same ID was rejected by Runtime, but its `finally` erased the **first call's** tracking ID. A subsequent socket disconnect could then fail to cancel that original pending local approval and in-flight action.

**Now:** Before adding an active call or invoking Dispatcher, the Agent rejects **duplicate in-flight Request IDs** as a protocol violation and closes that Cloud socket with WebSocket code **1008**. It deliberately does **not** emit a `tool.error` frame using the duplicate ID: Cloud might associate the duplicate failure with the original pending request. The established `close` handler still calls `runtime.cancel` for every original active request and aborts all active media transfers. Valid distinct IDs and the existing legacy Cloud management/normal tool path are unchanged.

**Proof:** `test/transport/phase18-duplicate-call.test.js` uses actual loopback WebSocket, `createCloudAgent`, `createRuntime`, ASK permission and `ApprovalQueue`. First test reproduces a pending cache approval, sends the duplicate, verifies 1008 close, original cancellation, queue cleanup, and absence of ambiguous same-ID result/error. Second confirms **two distinct in-flight approvals** are both cancelled when the socket disconnects.

## Fix 2 — MEDIUM: Browser masks typed cancellation and revocation failures

**Before:** In `src/services/browser.js`, `goto`, `browser_snapshot`, `targetFor`, `browser_click` and `browser_fill` had broad `catch` blocks that returned generic `BROWSER_*_FAILED` or `BROWSER_TARGET_NOT_FOUND` even when the original exception was `AgentError('REQUEST_CANCELLED')` or `AgentError('PERMISSION_DENIED')`.

**Now:** Catch blocks preserve **trusted typed `AgentError`** codes for lifecycle/policy/browser-validation errors, while still converting untyped Playwright and network exceptions into safe, non-sensitive Browser errors. The navigation guard continues to cancel its pending navigation grant on any failure. This is error propagation only; network restrictions, approval policy, side-effect commit boundaries and browser profile lifecycle were not changed.

**Proof:** `test/browser/phase18-error-codes.test.js` injects controlled fake Playwright operations to cover navigation revocation/cancellation, snapshot cancellation/revocation, locator/click/fill lifecycle failures, and an ordinary uncoded Playwright navigation failure. Expected error codes are compared directly, including policy revocation after the mocked page.goto() returns but before navigation confirmation.
