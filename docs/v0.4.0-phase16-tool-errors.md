# Phase 16 — Enhanced Tool Cancellation and Error Diagnostics (2026-10-13)

**Scope:** Agent v0.4.0 only. The separate `bdxa.buildifyx.com` backend was inspected **read-only** and was not modified. No live ChatGPT/production device end-to-end qualification is claimed.

## Error flow verified

1. The permission controller emits `permission.requested` for each Image/Browser/Cache `ASK` evaluation. A user **Deny** results in `PERMISSION_DENIED`; no interactive approval capability results in `CONFIRMATION_REQUIRED`. If Cloud sends `tool.cancel` during a pending approval, the request lifecycle aborts, the queue removes the prompt and the dispatch fails with `REQUEST_CANCELLED`.
2. The dispatcher retains the originating error code for `AgentError` and for known legacy plain `Error` instances such as `CACHE_NOT_FOUND` and `BROWSER_PROFILE_IN_USE`. Previously these plain coded errors became `INTERNAL_ERROR`. Unknown OS/dependency errors retain their message **internally** for local debugging but become generic `INTERNAL_ERROR` in public responses.
3. New `normalizeToolError` / `publicToolError` helpers in `src/core/errors.js` provide stable error codes with **safe public text**. Only a validated `category` and `toolName` may be included as public permission details. Raw paths, URLs, form values, Authorization secrets, OS stack traces and arbitrary nested error details are not forwarded to clients.
4. `src/core/dispatcher.js` reports redacted `tool.failed` / `tool.rejected` event diagnostics, without changing the existing internal error propagated to trusted runtime callers. `src/transport/cloud.js` now emits safe `tool.error` payloads; `src/transport/mcp/response.js` also returns safe structured MCP errors. Local Agent control `tool.call` in `src/cli/commands/local-instance.js` forwards the same safe envelope to the Local MCP gateway; command execution and policy decision semantics were not changed.
5. A **controlled loopback Cloud WebSocket** test verifies `read_image` **PERMISSION_DENIED**, `list_cached_assets` **PERMISSION_DENIED**, pending `browser_open` **REQUEST_CANCELLED**, and an Agent without interactive prompt support **CONFIRMATION_REQUIRED** as actual `tool.error` frames. All error payloads are tested against synthetic secret leakage. Additional tests check error-code preservation, rejected/expired approvals, event redaction and local MCP response serialization.

## Cloud-only boundary (unmodified; separate Cloud work item)

The Cloud `backend/src/modules/agent/websocket.ts` forwards `tool.error` into `manager.rejectToolResult`. The Cloud manager currently preserves an Agent's error **code** (when it matches the Browser code format) but deliberately substitutes a generic **Browser error message**; its own offline/timeouts use Cloud-specific codes such as `DEVICE_OFFLINE` and `DEVICE_REQUEST_TIMEOUT`. `backend/src/modules/mcp/server.ts` wraps the resulting error into MCP `isError` text + structured error. Therefore the Agent's public message is **not guaranteed** to appear verbatim in ChatGPT. Error sanitization of responses from **older/misbehaving peers**, Cloud-only timeout mapping, and exact ChatGPT client rendering require a **separate Cloud review/plan**. This Phase does not modify the Cloud gateway.
