# v0.4.0 — Browser Screenshots, Diagnostics and Artifacts

Browser screenshots and diagnostics require their own local permissions. Temporary capture artifacts and sensitive diagnostic data follow separate security and retention rules.

## MCP tools

| Tool | Permission | Parameters |
| --- | --- | --- |
| `browser_screenshot` | `browserCapture` | `sessionId`, optional `tabId`, `mode: viewport/fullPage/element`, `target` (for element), `format: png/jpeg`, `viewportPreset: mobile/desktop`, `viewport: {width,height}`, `deviceScaleFactor: 1..3`, `scale: css/device`, `timeoutMs`, `label`, `compareToArtifactId` |
| `browser_diagnostics` | `browserDiagnostics` | `sessionId`, `category: all/console/pageerror/network`, `limit` (1–100), `sinceId` |

Both permissions default to **Ask**, separate from `browserRead`, `imageRead`, `write` and full command access. The MCP registry exposes 29 tools total. Existing Agent Protocol v2 and Management Protocol v1 are unchanged.

## Screenshot and temporary artifact contract

- Capture viewport, full scrollable page or one unique visible element through Playwright. PNG/JPEG only. Standard Playwright screenshots disable animations and hide the caret; the opt-in CDP device-metrics path captures directly and may include an animation frame or caret, so it is not guaranteed to be frame-identical. Element screenshot rejects a directly selected password/file input; however complete screenshots **may contain credentials or personal data**, so capture requires a separate permission.
- Screenshot pixels are validated by the existing Image Service and stored **locally** in the owner-scoped private Artifact Cache: `kind=screenshot`, `origin=capture`, temporary by default. The user controls permanent storage explicitly with `save_cached_image`. `clear_cache` never removes already saved files.
- Limits: 16 MiB, 16 million pixels, 8192 pixels per side; cache defaults retain the Phase 2 24-hour TTL and device quota, plus checksum, lease, owner isolation and expiration. Oversized capture fails rather than silently saving a huge file.
- Local MCP transports screenshot bytes in bounded 128 KiB IPC chunks and constructs MCP ImageContent; an authenticated Cloud Server must negotiate Phase 4 binary capabilities. Without negotiation, Cloud gets only metadata and the artifact ID, with `imageBytesDelivered: false`. Cloud production compatibility requires separate validation.

## Phase 13 F05 — mobile/desktop layout and device-pixel captures

Existing calls remain unchanged: `browser_screenshot({sessionId})` captures the current viewport using CSS-pixel output. Optional `viewportPreset:"mobile"` (390×844 CSS pixels) uses temporary Chromium mobile **layout** metrics with default DPR 2; `viewportPreset:"desktop"` uses 1440×900 CSS pixels. Either preset can be replaced with a custom `viewport:{width,height}` between 240 and 4096 per dimension. Preset and custom viewport are mutually exclusive.

`deviceScaleFactor` accepts 1–3 (including 1.5); `scale:"device"` produces actual DPR-scaled native image pixels, while `scale:"css"` produces the viewport's CSS-pixel dimensions. For example, `{viewportPreset:"mobile",deviceScaleFactor:2,scale:"device"}` yields a 780×1688 PNG. Custom DPR is supported for viewport and fullPage captures, not element captures. The new fields operate on **one selected Chromium tab** using temporary CDP metrics and clear them in `finally`. The original Page viewport is restored after both success and failure; they do not persist in the profile or alter cookie storage.

Mobile layout emulation changes viewport and device-pixel ratio for responsive CSS; it **does not emulate a phone's real user agent, hardware, touch input, orientation, GPU or other native device features**. CDP is Chromium-specific. The capture enforces 16 million output pixels, 8192-pixel output sides and 16 MiB encoded bytes in addition to Image Cache validation. For `fullPage`, limits apply to the entire scrollable result at the requested output DPR. Invalid/oversized requests fail without caching an image.

## Before/after inspection

Call `browser_screenshot({sessionId,label:"before"})` to obtain an artifact ID, make an authorized UI change, then call `browser_screenshot({sessionId,label:"after",compareToArtifactId:beforeArtifactId})`. The result reports both IDs, native dimensions and `changedPercent`. Equal-size images are compared with up to 512×512 sampled pixels; a pixel is counted as different when an RGB channel differs by more than 12. Different native dimensions return `dimensionsMatch:false` and no percentage. This metric is approximate and **does not establish that a UI is bug-free**. Comparisons require both images to be screenshots in the same owner namespace.

## Privacy-aware browser diagnostics

Diagnostics are attached to each authorized Browser Context and kept **in memory**, bounded to the latest 160 events. `sinceId` supports a rolling inspection cursor; result size is capped at 100 events. Console events contain only severity and source origin, **never raw text/arguments**. Page errors expose only the coarse error type, **not the message or stack**. Failed network requests and HTTP 4xx/5xx show method, status, resource type and origin; no path, query, fragment, cookies, headers or response bodies are returned. Events are untrusted, incomplete after eviction, and not a proof of UI correctness.
