## Automated coverage added

1. **`test/transport/phase17-cloud-permissions.test.js`** runs a real loopback WebSocket server, actual `createCloudAgent`/Agent Runtime and real Sharp/Artifact Cache/Playwright Chromium services. It drives `tool.call` → local approval → `tool.result`/`tool.error` for:
   - `read_image`: ASK → **allow once** → result, ASK → **deny** → `PERMISSION_DENIED`, then explicit per-category ALLOW → result **without prompting**. Source image remains unchanged. Without negotiated binary Cloud relay, `imageBytesDelivered` remains **false**; a result is **not** proof of ChatGPT ImageContent rendering.
   - `list_cached_assets`: DENY → failure, ASK → deliberate approval → result, explicit ALLOW → result without prompt. Temporary artifacts stay in the isolated cache.
   - `browser_open`: DENY via `browserExternal` for external URL, DENY via `persistentProfile` for an explicitly requested persistent profile, ASK `browserNavigate` → deny, ASK → approve temporary Chromium on localhost, then explicit `browserNavigate:allow` → temporary browser session without prompting. `browserSensitive:deny` blocks explicit sensitive click.
   - `browser_screenshot`: ASK → deny; ASK → allow once and create a temporary screenshot artifact; explicit DENY → failure; explicit ALLOW → result without prompting. Never saves workspace files automatically or silently elevates persistent/sensitive/browser external categories.
   - Verifies queue emptied, no synthetic device token appears in results, no extra permanent workspace file is created, and successful metadata-only Cloud results do **not** fabricate binary ImageContent.
2. **Per-instance persistence**: creates actual policy files for two different instance IDs in an isolated temporary home. Tests that changes survive a reload, all 16 categories are present, A/O/F presets never elevate 11 advanced categories, second instance receives independent ASK defaults, and resetting one instance never modifies the other.
3. **Updated `test/browser/visual.test.js`**: a cross-workspace screenshot comparison still fails without data leakage, now with the exact **`CACHE_NOT_FOUND`** error introduced by Phase 16 rather than the older generic `INTERNAL_ERROR`. This was the only initially failing test in the full Phase 17 run; the precise code change is expected and the Browser Visual tests passed on rerun. Production access/isolation logic was not altered.
