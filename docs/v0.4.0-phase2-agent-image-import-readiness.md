# v0.4.0 — Phase 2: Agent Image Import Readiness & Minimal Adapter

Date: 2026-10-14
Plan: `v0.4.0 — ChatGPT Image Attachment → Agent Workspace Transfer`
Disposition: **Agent importer already sufficient; no Agent source adapter required.**

## Inspection

- `src/transport/cloud.js`: `device.ready` advertises optional `capabilities.media`; a valid `media.capabilities.accept` explicitly opts in to `image-import-v1`. No import is permitted for an old Cloud lacking that feature. Messages from previous or mismatched active WebSockets are dropped and authenticated reconnect calls `inbound.reset()`; disconnect calls `inbound.reset()` and clears temporary Cloud imports.
- `src/transport/media/protocol.js`: Media v1 feature list advertises `transfer-chunks-v1`, `image-content`, `image-import-v1`. Wire raw chunks are fixed at **131072 bytes (128 KiB)**.
- `src/transport/media/inbound.js`: Validates current source/socket epoch and exact `instanceId`, request/transfer IDs, version, chunk size, ordered index and offset, canonical Base64 bytes, announced size (max **4 MiB**), SHA-256 and supported PNG/JPEG/WebP MIME magic. Uses bounded serial work queue, ACK per chunk, 30-second in-flight idle timer and fail-closed cancellation/reset. Calls Agent image-service storage only after complete verified data; canImport is rechecked around asynchronous operations. This is an internal authenticated Cloud→Agent transport, not a ChatGPT attachment MCP tool.
- `src/image/service.js`: `__importCloudImage` verifies local `imageRead=allow` and `cacheManage=allow`, independently decodes real image bytes with Sharp, copies only to a private process-RAM map (two artifacts max, **5-minute TTL**) and returns `artifactId`/image metadata. `get_cached_image`/`__readImageBytes` check import permissions. `__clearCloudImports` zeroes imported buffers; permanent file creation requires the separate explicitly authorized `save_cached_image` operation. Historical cache artifacts remain separate from this RAM import path.
- `src/transport/mcp/tools/images.js` declares `get_cached_image`, `save_cached_image({artifactId,destinationPath})` and separate permission categories. Agent currently has no directly declared ChatGPT file-param MCP tool, correctly separating user-chat file ingress (Cloud responsibility) from authenticated bytes delivered over Agent WebSocket.

## Targeted regression added

New **`test/media/phase2-image-import-compat.test.js`**:

1. Real Agent ⇄ local mock WebSocket Cloud: an older Cloud accepting `transfer-chunks-v1` and `image-content` but not `image-import-v1` cannot open an inbound image import (`UNSUPPORTED_CAPABILITY`). Local workspace stays untouched; no RAM artifact appears.
2. Real Agent ⇄ local mock WebSocket Cloud: negotiated import of a PNG **greater than two 128-KiB chunks**; each chunk is ACKed; final `artifactId`/SHA-256 matches byte-for-byte Agent RAM image; no workspace file is created.

Tests use an ephemeral local WebSocket server, random test image, disposable directory and no user device credentials or deployed Cloud.
