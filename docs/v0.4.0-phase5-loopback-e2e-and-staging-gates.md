## Scope and decisions

- Investigated the **currently connected MCP tool catalog** and the read-only Cloud source; current Buildifyx tools have `create_image_upload`, `get_image_upload_status`, `get_uploaded_image`, `cancel_image_upload`, `send_uploaded_image_to_agent`, and Agent image/cache tools, but there is **no advertised tool with a host-provided file parameter**.
- OpenAI's official current plugin reference `https://developers.openai.com/plugins/reference#define-file-inputs` documents `_meta["openai/fileParams"]` on a tool descriptor, with an input object holding required `download_url` and `file_id` and optional declared `mime_type` and `file_name`. This means a **host-authorized file handoff is potentially implementable**. This does not prove that the user-chat image, especially one generated or displayed inside ChatGPT, is automatically or silently available to the MCP tool.
- The Cloud source, `backend/src/modules/mcp/server.ts`, currently registers a **browser-upload fallback**, not file-param direct input; repository search did not find `openai/fileParams` descriptor support. **Direct ChatGPT attachment → Agent is BLOCKED/NOT IMPLEMENTED**, not a passed E2E.
- Cloud source was read/tested, **not edited**. Cloud reports its own staging deployment/hosted OAuth tests outstanding. No real image attachment supplied in this turn; no authorized dedicated staging OAuth user, staging backend or test device/session was identified for this turn. Do not use existing production credentials to fake success.
